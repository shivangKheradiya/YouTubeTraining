# 🧮 Pointer Expressions

## Overview
Expressions involving **pointers** in C generally follow the same rules as other expressions. However, pointers introduce a few **special aspects** that are important to understand:  
- **Assignments**  
- **Conversions**  
- **Arithmetic**  

These operations make pointers flexible but also require careful handling to avoid errors.  

---

## 🛠️ Pointer Assignments
- You can assign one pointer to another if they are of the same type.  
```c
int x = 10;
int *p1, *p2;

p1 = &x;   /* p1 points to x */
p2 = p1;   /* p2 now points to the same location as p1 */
```
- Both `p1` and `p2` point to `x`.  

---

## 🛠️ Pointer Conversions
- Pointers can be converted between types, but this must be done carefully.  
- Example: casting a pointer to `void *` (generic pointer) and back.  
```c
int x = 42;
int *p = &x;
void *vp = p;       /* convert to void pointer */
int *q = (int *)vp; /* convert back to int pointer */
```
- Conversions are often used in functions that handle generic data.  

---

## 🛠️ Pointer Arithmetic
Pointer arithmetic is performed relative to the **base type** of the pointer:  
- `p + 1` → advances the pointer to the next element of its base type.  
- `p - 1` → moves the pointer to the previous element.  
- `p[n]` → equivalent to `*(p + n)`.  

### Example:
```c
int arr[5] = {10, 20, 30, 40, 50};
int *p = arr;

printf("%d\n", *(p + 2));  /* prints 30 */
printf("%d\n", p[2]);      /* also prints 30 */
```

- Both forms access the third element of the array.  

---

## 📌 Key Notes
- Pointer expressions behave like other expressions but operate on **addresses** instead of values.  
- Assignments must respect type compatibility.  
- Conversions allow flexibility but can be unsafe if misused.  
- Arithmetic is scaled by the size of the pointer’s base type.

- Apply pointer arithmetic to traverse arrays efficiently.  
- Recognize the equivalence between `p[n]` and `*(p+n)`.
