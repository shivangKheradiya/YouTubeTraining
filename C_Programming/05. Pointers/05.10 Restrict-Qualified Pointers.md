# 🚀 `restrict`-Qualified Pointers in C99

The **C99 standard** introduced a new type qualifier called `restrict`, which applies **only to pointers**. It’s designed to help the compiler optimize code by making assumptions about how memory is accessed.

---

### 🔑 What `restrict` Means
- A pointer declared with `restrict` is the **sole initial means of accessing the object** it points to.
- Other pointers may access the same object **only if they are derived from the restrict-qualified pointer**.
- This allows the compiler to assume that **no other unrelated pointer aliases the same memory**.

---

### ⚡ Why It Matters
- Normally, the compiler must assume that two different pointers might point to the same memory (aliasing).
- With `restrict`, the compiler can safely optimize because it knows the pointers refer to **non-overlapping memory regions**.
- This can lead to **faster code**, especially in numerical and array-processing routines.

---

### 📌 Typical Use Cases
- Function parameters (especially in performance-critical code).
- Pointers to memory allocated via `malloc()`.

---

### 🖥️ Example: Without and With `restrict`

```c
#include <stdio.h>

// Function without restrict
void add_arrays(int *a, int *b, int *c, int n) {
    for (int i = 0; i < n; i++) {
        c[i] = a[i] + b[i];
    }
}

// Function with restrict
void add_arrays_restrict(int * restrict a,
                         int * restrict b,
                         int * restrict c,
                         int n) {
    for (int i = 0; i < n; i++) {
        c[i] = a[i] + b[i];
    }
}

int main(void) {
    int x[5] = {1,2,3,4,5};
    int y[5] = {10,20,30,40,50};
    int z[5];

    add_arrays_restrict(x, y, z, 5);

    for (int i = 0; i < 5; i++) {
        printf("%d ", z[i]);
    }
    return 0;
}
```

---

### 🧠 Key Insight
- In `add_arrays_restrict()`, the compiler can assume that `a`, `b`, and `c` point to **different arrays**.
- This allows more aggressive optimizations (like vectorization).
- The **semantics of the program don’t change** — `restrict` only provides optimization hints.

---

### ⚠️ Important Notes
- Misusing `restrict` (e.g., if two restrict-qualified pointers actually alias the same memory) leads to **undefined behavior**.
- Always ensure that restrict-qualified pointers truly point to **non-overlapping memory**.
