# 📘 A Problem with `getchar()`

While `getchar()` is simple and widely used, it does come with a few important limitations that can affect how your program behaves—especially in interactive applications.

## ✅ Line‑Buffered Input

On many systems, `getchar()` is implemented using **line buffering**.  
This means:

- The function does **not** return a character immediately when a key is pressed  
- Instead, it waits until the user presses **ENTER**  
- Only then does it deliver the first character from the input line  

So even though `getchar()` reads a *single* character, the system may collect an entire line first.

This can lead to leftover characters sitting in the input buffer, which can be frustrating when you're trying to build real‑time or interactive programs.

---

## ✅ Why This Happens

Although the C standard allows `getchar()` to behave as a fully interactive, character‑by‑character input function, **most compilers do not implement it that way**. They rely on the operating system’s default line‑buffered input behavior.

So if your earlier program didn’t respond immediately to each keystroke, this buffering behavior is the reason.
