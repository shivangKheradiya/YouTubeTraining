# 📘 An Important Difference Between C and C++

C and C++ handle the names of **structures**, **unions**, and **enumerations** differently. Understanding this distinction is essential when writing portable code or moving code between the two languages.

---

## ✅ Structure Tags in C

Consider the following structure:

```c
struct MyStruct {
    int a;
    int b;
};
```

In **C**, the name `MyStruct` is a **tag**, not a complete type name.  
To declare a variable of this type, you must write:

```c
struct MyStruct obj;
```

The keyword `struct` is required because the tag alone does **not** represent a full type.

---

## ✅ Structure Names in C++

In **C++**, the same declaration behaves differently. Once the structure is defined, its tag becomes a **complete type name**. Therefore, you can write:

```c
MyStruct obj;   /* Valid in C++, invalid in C */
```

The keyword `struct` is optional in C++.  
However, using the C‑style form is still perfectly legal in C++:

```c
struct MyStruct obj;   /* Also valid in C++ */
```

---

## ✅ General Rule for C vs. C++

This difference applies not only to structures, but also to:

- **unions**
- **enumerations**

### In C:
You must write:

```c
struct MyStruct
union MyUnion
enum MyEnum
```

whenever you declare variables of these types.

### In C++:
You can simply write:

```c
MyStruct
MyUnion
MyEnum
```

without the keywords.

---

## ✅ Portability Considerations

- ✅ **C++ code can freely use C‑style declarations**, so porting C code to C++ is usually trouble‑free.  
- ⚠️ **C++ code that omits `struct`, `union`, or `enum` will NOT compile in C.**  
  When porting C++ code back to C, you must add the appropriate keywords.
