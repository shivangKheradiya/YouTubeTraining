# ⤴️ The `goto` Statement

## Overview
C provides a rich set of control structures (`if`, `switch`, `for`, `while`, `do-while`) along with `break` and `continue`. Because of this, there is **little need for `goto`** in most programs.  

The main concern with `goto` is that it can make programs **harder to read and maintain**. For this reason, it has largely fallen out of favor. However, in rare cases—such as **jumping out of deeply nested loops**—`goto` can be a convenient tool.  

---

## 🛠️ General Form
```c
goto label;
...
label:
```

- **label** → A valid identifier followed by a colon (`:`).  
- The label must be in the **same function** as the `goto`. You cannot jump between functions.  
- Control transfers unconditionally to the labeled statement.  

---

## 📌 Key Notes
- `goto` is not required in any programming situation, but can occasionally simplify code.  
- Overuse of `goto` leads to **spaghetti code** (unstructured, hard-to-follow logic).  
- Best practice: use structured control statements instead of `goto` whenever possible.  
- This book (and most modern programming practice) avoids `goto` except for demonstration.  

---

## ✔️ Example: Loop Using `goto`
```c
int x = 1;

loop1:
    x++;
    if (x <= 100) 
        goto loop1;
```

### Explanation
- `x` starts at 1.  
- The label `loop1` marks the beginning of the loop.  
- Each iteration increments `x`.  
- If `x <= 100`, control jumps back to `loop1`.  
- This creates a loop from 1 to 100.

- Recognize why `goto` is discouraged in modern programming.  
- Apply `goto` only in rare cases where structured alternatives are less practical.  
- Maintain readability by limiting or avoiding `goto` usage.
