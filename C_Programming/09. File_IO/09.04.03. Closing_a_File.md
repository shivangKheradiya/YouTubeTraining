# ✅ Closing a File with `fclose()` (C File I/O)

**`fclose()` terminates the connection between a stream and its underlying file, flushing any buffered output and releasing system resources.** It is essential to close every file you open, because failing to do so can lead to lost data, corrupted files, or running out of available file handles.

---

## 🔹 What `fclose()` Does

When you call `fclose()` on a stream:

- **Any buffered output is written to the file** (a flush operation)  
- The underlying file descriptor is formally closed by the operating system  
- The internal `FILE` structure is released for reuse  
- The stream becomes invalid and must not be used again  

Because systems limit how many files can be open at once, closing files promptly prevents resource exhaustion.

---

## 🔹 Function Prototype

```c
int fclose(FILE *fp);
```

- `fp` must be a valid file pointer returned by `fopen()`.

---

## 🔹 Return Values

- **0** → The file was closed successfully  
- **EOF** → An error occurred during flushing or closing

If `fclose()` returns `EOF`, you can call `ferror()` to determine what went wrong.

Typical causes of failure include:

- The disk being removed or unavailable  
- No remaining space to flush buffered data  

---

## 🔹 Why Closing Files Matters

Not closing a file can cause:

- **Lost data** (because buffered output never gets written)  
- **Corrupted files**  
- **Intermittent, hard‑to‑debug I/O errors**  
- **Running out of file handles**, preventing new files from being opened  

Closing files is therefore a critical part of safe and reliable C programming.
