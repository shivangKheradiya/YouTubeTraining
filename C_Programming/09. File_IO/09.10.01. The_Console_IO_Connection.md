# ✅ The Console I/O Connection

C treats console input and output almost exactly the same way it treats file input and output. In fact, the console I/O functions you normally use—such as `printf()`, `scanf()`, `putchar()`, and `getchar()`—are simply convenient wrappers around the same mechanisms used for file operations. Internally, they read from **`stdin`** and write to **`stdout`**, which are just predefined file streams created automatically when your program starts.

Because these standard streams behave like ordinary `FILE*` objects, **any file‑oriented function can operate on the console**, and any console‑oriented function can operate on files—*if the environment redirects the streams*. This is possible because operating systems such as Windows, DOS, and Unix allow **I/O redirection**, meaning `stdin` and `stdout` can be connected to files instead of the keyboard and screen.

---

## ✅ Example: Console Functions Acting Like File Functions

Consider this simple program:

```c
#include <stdio.h>

int main(void)
{
    char str[80];

    printf("Enter a string: ");
    gets(str);
    printf(str);

    return 0;
}
```

If you run this program normally, it:

1. Prints a prompt to the screen (`stdout`)
2. Reads input from the keyboard (`stdin`)
3. Prints the input back to the screen

But in an environment that supports redirection, the same program can behave very differently.

---

## ✅ Redirecting Output

Running:

```
TEST > OUTPUT
```

sends everything normally printed to the screen into a file named **OUTPUT**.  
This works because `stdout` has been redirected by the operating system.

---

## ✅ Redirecting Both Input and Output

Running:

```
TEST < INPUT > OUTPUT
```

causes:

- `stdin` to read from the file **INPUT**
- `stdout` to write to the file **OUTPUT**

The program itself does not change—only the streams it uses are redirected.

This behavior is possible because `stdin`, `stdout`, and `stderr` are simply file streams that the OS can reassign to different devices or files.

---

## ✅ After Program Termination

When the program exits, the operating system automatically restores the standard streams to their default state (keyboard and screen). No cleanup is required in your code.
