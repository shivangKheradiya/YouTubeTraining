# Streams

The C file system is built to work with many different kinds of hardware—keyboards, screens, disk files, tape drives, and more. Even though these devices behave differently at the hardware level, the C library hides those differences by presenting each device as a **stream**.  

A stream is a logical data channel. Because streams are device‑independent, the same I/O functions you use to write to a file can also write to the console or any other supported device. C defines two categories of streams: **text streams** and **binary streams**.

---

## Text Streams

A **text stream** represents data as a sequence of characters. According to the C standard:

- Text is divided into lines.
- Each line ends with a newline character, although the final line may omit it.
- The system may translate certain characters when reading or writing.  
  For example, on some systems a newline written by your program might be stored as a carriage‑return/linefeed pair on disk.

Because of these translations:

- What your program writes may not match exactly what is stored externally.
- The number of characters processed by your program may differ from the number of bytes physically written to the device.

---

## Binary Streams

A **binary stream** represents data as raw bytes with no interpretation or translation.

Key characteristics:

- Every byte written by the program corresponds exactly to a byte stored on the device.
- No character conversions occur.
- The number of bytes read or written matches exactly what appears in the external file.
- Some implementations may add padding bytes (often nulls) to align data—for example, to fill a disk sector.

Binary streams are ideal when you need precise control over the data layout, such as when storing structures or working with non‑text data formats.
