# Files

In C, the word *file* refers to any external data source or destination your program can communicate with—this includes not only disk files, but also devices like terminals, printers, and more. To work with a file, your program first **opens** it, which creates an association between that file and a **stream**. Once the stream is established, your program can read from or write to the file through the standard I/O functions.

---

## Different files, different capabilities

Although all streams behave uniformly from the program’s point of view, the underlying files or devices do not all support the same operations. For example:

- A disk file allows random access (you can move around within it).
- A printer typically supports only sequential output.

This distinction is important: **streams provide a unified interface, but the actual files differ in what they can do**.

---

## File position indicator

When a file supports positioning, opening it sets its internal position indicator to the beginning. Each time your program reads or writes a byte, this indicator advances automatically, ensuring that operations proceed through the file in order unless you explicitly reposition it.

---

## Closing a file

When you are finished with a file, you **close** it. Closing a file:

- Breaks the association between the stream and the external device.
- Flushes any buffered output so nothing is left unwritten.
- Releases system resources.

If your program ends normally—either by returning from `main()` or by calling `exit()`—all open files are closed automatically. However, abnormal termination (such as a crash or a call to `abort()`) does **not** guarantee that files will be closed or buffers flushed.

---

## The `FILE` structure

Every open stream is represented internally by a control structure of type `FILE`. This structure is managed entirely by the C library. You should never attempt to modify it directly.

---

## Why streams and files are separate

If you’re new to C, the distinction between streams and files may feel unnecessary. But this separation is what allows the I/O system to present a **single, consistent interface** for all devices. You write your code in terms of streams, and the library handles the details of interacting with the actual hardware or file system.
