# ✅ Using `freopen()` to Redirect Standard Streams

**`freopen()` lets you take an already‑open stream—such as `stdin`, `stdout`, or `stderr`—and attach it to a different file.** This effectively redirects where input comes from or where output goes. According to TutorialKart, `freopen()` is specifically designed for reassigning existing streams, especially the standard ones. IBM’s documentation confirms that it closes the current file associated with the stream and reopens it using the new filename and mode.

---

## 🔹 Function Prototype

```c
FILE *freopen(const char *filename, const char *mode, FILE *stream);
```

### Parameters

- **`filename`** — the name of the file you want the stream to use  
- **`mode`** — same values as used with `fopen()` (e.g., `"r"`, `"w"`, `"a"`)  
- **`stream`** — an existing stream such as `stdin`, `stdout`, or `stderr`

### Return Value

- Returns the **same stream pointer** on success  
- Returns **NULL** if the operation fails  

This behavior is confirmed in both TutorialKart and IBM’s documentation.

---

## ✅ Example: Redirecting `stdout` to a File

The following program redirects all output normally sent to the screen into a file named **OUTPUT**:

```c
#include <stdio.h>

int main(void)
{
    char str[80];

    freopen("OUTPUT", "w", stdout);

    printf("Enter a string: ");
    gets(str);
    printf(str);

    return 0;
}
```

### What happens here?

- `freopen("OUTPUT", "w", stdout);`  
  closes the current `stdout` and reassigns it to the file **OUTPUT**.

- Every call to `printf()` now writes into that file instead of the console.

This is exactly the behavior described in IBM’s reference: the stream is closed and reassigned to the new file.

---

## ✅ When to Use `freopen()`

`freopen()` is most useful in **specialized situations**, such as:

- Debugging (capturing output to a file)
- Automated testing
- Replacing console input with scripted input files
- Redirecting error messages to logs

However, as your text notes, using redirected `stdin`/`stdout` for heavy disk I/O is **less efficient** than using binary functions like `fread()` and `fwrite()`. Those functions operate on raw data and avoid the overhead of formatted text processing.
