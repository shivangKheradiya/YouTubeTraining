# ✅ Reading a Character from a File

**C provides two equivalent functions for reading a single character from a file: `getc()` and `fgetc()`.**  
They behave the same way, and both return the next byte from the stream as an `int`.

---

## 🔹 `getc()` and `fgetc()` — What They Are

C defines two functions for character input:

- **`getc()`** — often implemented as a macro for speed  
- **`fgetc()`** — always a real function call  

Both exist for historical compatibility, and you may use either one.

---

## 🔹 Function Prototype

```c
int getc(FILE *fp);
```

- `fp` must be a valid file pointer returned by `fopen()`.

Although the return type is `int`, the actual character is stored in the **low‑order byte**.  
The higher‑order bytes are zero unless an error occurs.

---

## 🔹 Return Values

`getc()` returns:

- **The character read** (as an `unsigned char` converted to `int`)  
- **`EOF`** if:
  - The end of the file is reached  
  - An input error occurs  

This behavior is confirmed in standard references: both `getc()` and `fgetc()` return `EOF` for end‑of‑file or error conditions.

Because `EOF` signals *two different situations*, you must use:

- **`feof(fp)`** → to check if the end of the file was reached  
- **`ferror(fp)`** → to check if an error occurred  

---

## 🔹 Example: Reading Until End‑of‑File

```c
int ch;

do {
    ch = getc(fp);
} while (ch != EOF);
```

This loop continues until `getc()` returns `EOF`.  
To distinguish between end‑of‑file and an error, call `feof()` or `ferror()` afterward.

---

## ✅ Summary

- **`getc()` and `fgetc()` read one character at a time.**  
- **They return an `int`, not a `char`, so they can signal `EOF`.**  
- **`EOF` may indicate end‑of‑file or an error—use `feof()` and `ferror()` to tell which.**
