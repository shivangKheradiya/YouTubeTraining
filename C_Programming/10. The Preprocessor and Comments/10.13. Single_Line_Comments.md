# ✅ Single‑Line Comments

C99 introduced support for **two comment styles**: the traditional `/* … */` multiline comment and the **single‑line comment**, which begins with `//` and continues to the end of the line. As cppreference explains, everything after `//` on that line is ignored by the compiler. This style is also used in C++, which is why it is often called a *C++‑style comment*.

### ✅ Example

```c
// this is a single-line comment
```

Single‑line comments are especially convenient when you want to annotate code briefly, one line at a time.

---

## ✅ Compatibility with C89

C89 does **not** officially support `//` comments. Stack Overflow notes that strict C89 compilers will reject them, but many modern compilers accept them as an extension. C99 standardized their use, and virtually all contemporary compilers now support them.

---

## ✅ Nesting Behavior

A `//` comment **can appear inside a multiline comment**, because the entire `/* … */` block is treated as one comment unit. For example:

```c
/* this is a // test of nested comments. */
```

This is valid because the `//` is simply part of the text inside the block comment. cppreference confirms that comment contents are ignored as raw text.

---

## ✅ Best Practices for Commenting

Comments should be used to clarify code whenever needed. Good practice includes:

- Adding a brief description at the top of each non‑trivial function  
- Explaining what the function does  
- Describing how it should be called  
- Stating what it returns  

Clear comments make code easier to understand, maintain, and debug—something emphasized in programming guides such as Compile N Run’s overview of C comments.
