# ✅ The `#undef` Directive

The **`#undef`** directive is used to *remove* a macro definition that was previously created with `#define`. According to Microsoft’s documentation, `#undef` simply erases the current definition of the identifier, and any later occurrences of that name will no longer be treated as a macro. The GNU Preprocessor manual confirms that `#undef` takes only the macro name and has no effect if the name was never defined.

---

## ✅ What `#undef` Does

When the preprocessor encounters:

```c
#undef MACRO_NAME
```

it deletes the macro definition associated with `MACRO_NAME`. After this point, the identifier behaves like an ordinary token again.

### Example

```c
#define LEN 100
#define WIDTH 100

char array[LEN][WIDTH];

#undef LEN
#undef WIDTH
/* At this point, both LEN and WIDTH are undefined */
```

- Before the `#undef` lines, `LEN` and `WIDTH` expand to `100`.
- After `#undef`, they no longer have any macro meaning.

---

## ✅ Why Use `#undef`?

Search results highlight several practical uses:

### **1. Localizing macro definitions**  
Microsoft notes that `#undef` is often paired with `#define` to give a macro meaning only within a specific region of code. This prevents accidental reuse elsewhere.

### **2. Redefining a macro**  
The GNU documentation explains that if you want to redefine a macro with a new value, you must first `#undef` it.

### **3. Avoiding name conflicts**  
Large projects or multiple header files may define the same macro name. Sanfoundry points out that `#undef` helps prevent such conflicts by clearing unwanted definitions.

### **4. Ensuring a macro is not defined**  
Microsoft states that you can safely `#undef` a name even if it was never defined, guaranteeing that it is treated as undefined.

---

## ✅ Summary

- **`#undef` removes a macro definition.**
- It is commonly used to **limit the scope** of macros.
- It is also used to **redefine** macros safely.
- It helps avoid **macro name collisions** in large codebases.
