# ✅ The `#error` Directive

The **`#error`** directive is a preprocessor instruction that immediately stops compilation and displays a custom error message. According to Microsoft’s documentation, `#error` emits the specified message and then terminates the build process. cppreference also confirms that encountering `#error` makes the program *ill‑formed*, forcing the compiler to abort.

---

## ✅ What `#error` Does

When the preprocessor encounters a `#error` directive, it:

- Prints the message you provide  
- Stops compilation immediately  
- May include additional diagnostic information depending on the compiler  

This makes it especially useful for **debugging**, **configuration checks**, and **conditional compilation**.

---

## ✅ Syntax

```c
#error error-message
```

### Important details:

- The message **is not placed in quotes**.  
- The message is treated as raw tokens and displayed exactly as written.  
- The directive is typically used inside conditional compilation blocks.

Example from Microsoft’s documentation:

```c
#if !defined(__cplusplus)
#error C++ compiler required.
#endif
```

If the condition is true, the compiler prints:

```
error: C++ compiler required.
```

and stops.

---

## ✅ Why Use `#error`?

Developers commonly use `#error` to:

- Enforce required compiler settings  
- Prevent compilation on unsupported platforms  
- Catch missing macro definitions  
- Flag invalid configuration states  
- Provide clear messages during debugging  

For example, Stack Overflow shows a case where `#error` is used to halt compilation when a required macro is not defined.

---

## ✅ Example

```c
#ifndef VERSION
#error VERSION must be defined before compiling
#endif
```

If `VERSION` is not defined, compilation stops with the message:

```
VERSION must be defined before compiling
```
