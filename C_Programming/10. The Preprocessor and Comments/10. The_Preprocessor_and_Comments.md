# ✅ Preprocessor Directives and Comments

In C, you can embed special instructions directly into your source code that tell the compiler how to prepare the program before actual compilation begins. These instructions are known as **preprocessor directives**, and they significantly extend what you can do in the programming environment. According to standard references, the C preprocessor runs *before* the compiler and performs tasks such as file inclusion, macro expansion, and conditional compilation.

Preprocessor directives always begin with the `#` symbol and are handled by the preprocessor as a separate step before the compiler sees your code. This makes them powerful tools for organizing programs, controlling compilation, and improving code flexibility.

Alongside these directives, C also supports **comments**, which allow you to document your code or temporarily disable sections of it. Comments are removed by the preprocessor before compilation, meaning they have no effect on the final executable.

---

# ✅ Key Points

- **Preprocessor directives** are instructions processed *before* compilation.  
  They include features such as:
  - **Macros** (`#define`)  
  - **File inclusion** (`#include`)  
  - **Conditional compilation** (`#ifdef`, `#if`, etc.)  
  - **Other directives** like `#undef` and `#pragma`  
  These categories are described in detail in GeeksforGeeks and Wikibooks references.

- Directives **expand the capabilities** of the language by allowing text substitution, modular code organization, and selective compilation.

- **Comments** (`/* ... */` and `// ...`) help document code and are stripped out before compilation, as explained in Stack Overflow discussions about preprocessing order.

Together, preprocessor directives and comments give you more control over how your program is built and make your code easier to understand and maintain.
