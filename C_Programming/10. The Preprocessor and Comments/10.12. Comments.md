# ✅ Comments

In **C89**, the language defines only **one** form of comment: a block comment that begins with `/*` and ends with `*/`. As Microsoft’s documentation explains, everything between these two delimiters is completely ignored by the compiler. Importantly, there must be **no space** between the slash and the asterisk in either delimiter.

### ✅ Basic Example

```c
printf("hello");
/* printf("there"); */
```

Only `"hello"` is printed because the commented-out line is ignored.

---

## ✅ Multiline Comments

This comment style is often called a **multiline comment** because it can span multiple lines:

```c
/* this is a
   multiline
   comment */
```

The compiler treats the entire block as a single whitespace character, as confirmed by Microsoft’s documentation.

---

## ✅ Where Comments May Appear

Comments may appear almost anywhere in a program **as long as they do not break tokens**. For example:

✅ Valid:

```c
x = 10 + /* add the numbers */ 5;
```

❌ Invalid:

```c
swi/*this will not work*/tch(c);
```

Here, the comment interrupts the keyword `switch`, which is not allowed. cppreference notes that comments can appear anywhere whitespace is permitted, but not inside identifiers or keywords.

---

## ✅ Comments Cannot Be Nested

C89 does **not** allow nested block comments. If you attempt to place one `/* ... */` comment inside another, the compiler will treat the first `*/` it encounters as the end of the comment, causing errors. This is confirmed by multiple sources, including Riptutorial and Stack Overflow.

Example of invalid nested comments:

```c
/* this is an outer comment
   x = y / a;
   /* this is an inner comment — causes an error */
*/
```

The inner `/*` disrupts the structure, and the compiler cannot match the delimiters correctly.
