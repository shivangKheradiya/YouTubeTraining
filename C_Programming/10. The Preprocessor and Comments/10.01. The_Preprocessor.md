# ✅ The C Preprocessor

The C **preprocessor** handles a set of special instructions—called **preprocessor directives**—before the compiler processes your code. These directives allow you to include files, define macros, control conditional compilation, and more. According to GeeksforGeeks and Cprogramming.com, all preprocessor directives begin with the `#` symbol and are processed before compilation begins.

Here is a representative list of common directives:

- `#define`  
- `#undef`  
- `#include`  
- `#if`  
- `#elif`  
- `#else`  
- `#endif`  
- `#ifdef`  
- `#ifndef`  
- `#error`  
- `#pragma`  
- `#line`

These directives give you powerful control over how your program is built, enabling macro substitution, conditional compilation, and file inclusion.

---

## ✅ Rules for Preprocessor Directives

Two important rules apply to all preprocessor directives:

### **1. They must begin with `#`**  
This is how the preprocessor recognizes them. IBM’s documentation confirms that directives are “lines of the source file beginning with the character `#`”.

### **2. Each directive must appear on its own line**  
The C preprocessor is **line‑oriented**, meaning each directive must occupy a separate line of code. Codeforwin explicitly notes that preprocessor statements “start in a separate line” and end with a newline.

Because of this, the following is **invalid**:

```c
#include <stdio.h> #include <stdlib.h>
```

Each `#include` must appear on its own line.

---

## ✅ Why This Matters

The preprocessor runs before the compiler and transforms your source code into a new version that the compiler then processes. If directives are not formatted correctly, the preprocessor cannot interpret them, leading to compilation errors.

Understanding these rules ensures that your macros, includes, and conditional compilation blocks behave exactly as intended.
