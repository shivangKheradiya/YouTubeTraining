# ✅ Using the `defined` Operator

The C preprocessor provides another way to test whether a macro exists: the **`defined`** operator. This operator is used inside a `#if` directive and evaluates to **true** if the specified macro name has been defined earlier with `#define`. As the Digital/UNIX documentation explains, `defined` is part of the standard conditional‑compilation system and works alongside `#if`, `#elif`, and related directives.

---

## ✅ General Form

```c
defined MACRO_NAME
```

If `MACRO_NAME` is currently defined, the expression evaluates to true; otherwise, it evaluates to false.

This allows you to write:

```c
#if defined MYFILE
```

which behaves exactly like:

```c
#ifdef MYFILE
```

Both forms check whether `MYFILE` has been defined.

---

## ✅ Negating the Condition

You can combine `defined` with the logical negation operator `!` to test whether a macro is **not** defined:

```c
#if ! defined DEBUG
    printf("Final version!\n");
#endif
```

This block is compiled only when `DEBUG` has *not* been defined. Sanfoundry’s overview of conditional compilation confirms that such tests are evaluated at compile time and determine which code is included in the final program.

---

## ✅ Why Use `defined`?

While `#ifdef` and `#ifndef` handle simple cases, the `defined` operator is especially useful because it can appear inside **`#elif` expressions**, allowing more complex conditional chains. StackOverflow discussions highlight this as a key advantage when building multi‑branch compile‑time logic.

For example:

```c
#if defined FEATURE_A
    /* code for A */
#elif defined FEATURE_B
    /* code for B */
#else
    /* fallback */
#endif
```

This pattern is common in portable or configurable software where multiple compile‑time options may exist.
