# 🌐 The `extern` Storage Class

## Overview
The **`extern` specifier** in C is used to declare variables with **external linkage**—meaning they are defined elsewhere in the program but accessible across multiple files or modules. It allows you to reference global variables without creating new storage for them.  

To fully understand `extern`, it’s important to distinguish between **declarations** and **definitions**:  
- **Declaration** → Introduces the name and type of an object.  
- **Definition** → Allocates storage for the object.  
An object may have many declarations but only one definition.

---

## 🔑 Linkage Categories in C
C defines three categories of linkage that determine identifier visibility across files:  

- **External linkage** → Functions and global variables accessible across all files in a program.  
- **Internal linkage** → File-scope objects declared with `static`, visible only within their file.  
- **No linkage** → Local variables, visible only within their block.  

---

## 📝 Using `extern`
By preceding a variable with `extern`, you declare it without defining it. This is useful when:  
- The variable is defined later in the same file.  
- The variable is defined in another file of a multi-file program.  

### Example: Declaring before definition
```c
#include <stdio.h>

int main(void) {
    extern int first, last; // declare global vars
    printf("%d %d", first, last);
    return 0;
}

// global definition of first and last
int first = 10, last = 20;
```

**Output:**
```
10 20
```

Here, `extern` tells the compiler that `first` and `last` exist elsewhere, allowing them to be used before their definition.

---

## ⚖️ Important Notes
- If you initialize an `extern` variable, the declaration becomes a **definition**.  
- If global variables are declared before use, `extern` is not required.  
- The compiler resolves undeclared variables by checking enclosing blocks, then global scope.  

---

## 🌍 Multi-File Programs
`extern` is especially important in programs spread across multiple files:  

**File One**
```c
int x, y;
char ch;

int main(void) {
    /* ... */
}

void func1(void) {
    x = 123;
}
```

**File Two**
```c
extern int x, y;
extern char ch;

void func22(void) {
    x = y / 10;
}

void func23(void) {
    y = 10;
}
```

Here, `extern` ensures that `x`, `y`, and `ch` are recognized in File Two without redefining them. The linker resolves all references during compilation.

---

## 📌 Best Practice
- In real-world projects, `extern` declarations are typically placed in **header files** (`.h`) and included in each source file.  
- This avoids duplication and reduces errors.  

---

## ⚠️ Special Note
- `extern` can also be applied to function declarations, but this is redundant since functions already have external linkage by default.
