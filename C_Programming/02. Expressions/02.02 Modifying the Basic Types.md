# 🔧 Modifying the Basic Types

## Overview
Beyond the five foundational data types, C allows **type modifiers** to refine the meaning of a base type. These modifiers enable developers to tailor data types for specific needs such as precision, range, or signedness.  

With the exception of `void`, all basic types can be modified.

---

## 🛠️ Type Modifiers
The following modifiers can precede basic types:

- `signed`  
- `unsigned`  
- `long`  
- `short`  

### Valid Combinations
- `int` → can be modified by `signed`, `unsigned`, `short`, `long`  
- `char` → can be modified by `signed`, `unsigned`  
- `double` → can be modified by `long`  
- C99 → introduces `long long` for extended integer range  

---

## 📊 Data Type Sizes and Ranges
Below is a summary of typical sizes and minimal ranges defined by the C standard:

| Type                  | Typical Size (bits) | Minimal Range |
|-----------------------|----------------------|---------------|
| `char`                | 8                   | –127 to 127 |
| `unsigned char`       | 8                   | 0 to 255 |
| `signed char`         | 8                   | –127 to 127 |
| `int`                 | 16 or 32            | –32,767 to 32,767 |
| `unsigned int`        | 16 or 32            | 0 to 65,535 |
| `signed int`          | 16 or 32            | Same as `int` |
| `short int`           | 16                  | –32,767 to 32,767 |
| `unsigned short int`  | 16                  | 0 to 65,535 |
| `signed short int`    | 16                  | Same as `short int` |
| `long int`            | 32                  | –2,147,483,647 to 2,147,483,647 |
| `long long int` (C99) | 64                  | –(2^63 – 1) to 2^63 – 1 |
| `unsigned long int`   | 32                  | 0 to 4,294,967,295 |
| `unsigned long long int` (C99) | 64 | 0 to 2^64 – 1 |
| `float`               | 32                  | 1E–37 to 1E+37 (6 digits precision) |
| `double`              | 64                  | 1E–37 to 1E+37 (10 digits precision) |
| `long double`         | 80                  | 1E–37 to 1E+37 (10 digits precision) |

## ⚖️ Signed vs. Unsigned
- **Signed integers**: Default in C. High-order bit is interpreted as a **sign flag**.  
  - `0` → positive  
  - `1` → negative  
- **Unsigned integers**: Extend the positive range by using all bits for magnitude.  

### Example
- `signed int` max: **32,767**  
- `unsigned int` max: **65,535**  

Binary representation of `32,767`:  
```
0111111111111111
```
If the high-order bit is set to `1`:  
- As `signed int` → –1  
- As `unsigned int` → 65,535  

---

## 🧮 Two’s Complement Representation
Negative numbers in C are generally represented using **two’s complement**:
1. Reverse all bits (except the sign flag).
2. Add 1.
3. Set the sign flag to 1.

This method ensures efficient arithmetic operations and consistent representation across platforms.

---

## 📌 Notes
- Using `signed` with `int` is redundant since `int` is signed by default.  
- The most important use of `signed` is with `char`, especially on systems where `char` defaults to unsigned.  
- When a modifier is used alone, `int` is implied:  
  - `signed` → `signed int`  
  - `unsigned` → `unsigned int`  
  - `long` → `long int`  
  - `short` → `short int`  

Although `int` is implied, modern practice is to **explicitly specify `int`** for clarity.
