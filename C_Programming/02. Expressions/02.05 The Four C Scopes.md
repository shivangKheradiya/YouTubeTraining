# 🔎 The Four C Scopes

## Overview
In C, identifiers (names of variables, functions, labels, etc.) have **scope**, which defines where they are visible and accessible in a program. While we often use the broad terms *local* and *global*, the C standard refines these into **four distinct scopes**.  

Understanding these scopes is essential for writing clear, modular, and bug-free code.

---

## 🛠️ The Four Scopes

| Scope                  | Meaning |
|-------------------------|---------|
| **File Scope**          | Begins at the start of a file (translation unit) and ends at the file’s end. Applies to identifiers declared outside all functions. File scope identifiers are visible throughout the file. Variables with file scope are **global**. |
| **Block Scope**         | Begins with `{` and ends with the corresponding `}`. Includes function parameters as part of the function’s block scope. Variables with block scope are **local** to their block. |
| **Function Prototype Scope** | Applies to identifiers declared in a function prototype. These identifiers are visible only within the prototype itself. |
| **Function Scope**      | Begins with `{` of a function and ends with its `}`. Applies only to **labels** (used with `goto`). A label must be in the same function as the `goto` that references it. |

---

## 📌 Key Notes
- **File scope** → Global variables and functions accessible throughout the file.  
- **Block scope** → Local variables and parameters accessible only within their block.  
- **Function prototype scope** → Temporary identifiers used in prototypes, not visible elsewhere.  
- **Function scope** → Special case for labels used with `goto`.  

---

## ⚖️ Practical Implications
- Most programming discussions simplify scope into **local vs. global**, but knowing the finer distinctions helps avoid errors.  
- **Block scope** ensures variables are isolated within functions or inner blocks, preventing accidental interference.  
- **File scope** makes data available across functions but should be used sparingly to avoid side effects.  
- **Function prototype scope** is rarely discussed but important for clarity in function declarations.  
- **Function scope** is specialized and applies only to labels, ensuring `goto` targets remain within the same function.
