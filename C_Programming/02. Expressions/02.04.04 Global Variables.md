# 🌍 Global Variables

## Overview
**Global variables** are variables declared **outside of all functions**. Unlike local variables, they are accessible throughout the entire program and retain their values for the program’s entire execution.  

Global variables are useful when multiple functions need to share the same data, but they must be used carefully to avoid unintended side effects.

---

## 📝 Declaration of Global Variables
Global variables are declared outside any function, typically at the **top of the program** for clarity.

**Example:**
```c
#include <stdio.h>

int count; /* count is global */

void func1(void);
void func2(void);

int main(void) {
    count = 100;   // global variable initialized
    func1();
    return 0;
}

void func1(void) {
    int temp;
    temp = count;  // accessing global variable
    func2();
    printf("count is %d", count); // prints 100
}

void func2(void) {
    int count; // local variable hides global count
    for(count = 1; count < 10; count++)
        putchar('.');
}
```

---

## 🔎 Key Observations
- `count` is declared globally and can be accessed by both `main()` and `func1()`.  
- In `func2()`, a **local variable** named `count` hides the global variable. Inside `func2()`, all references to `count` refer to the local version, not the global one.  
- This demonstrates **scope rules**: local variables take precedence over global variables when names conflict.  

---

## ⚖️ Characteristics of Global Variables
- **Scope:** Entire program (all functions can access them).  
- **Lifetime:** Exist for the duration of the program.  
- **Storage:** Allocated in a fixed memory region reserved by the compiler.  
- **Persistence:** Retain values between function calls.  

---

## ⚠️ Best Practices & Pitfalls
- ✅ Use global variables when multiple functions genuinely need to share the same data.  
- ❌ Avoid unnecessary global variables:
  - They consume memory for the entire program run.  
  - They reduce modularity, making functions dependent on external state.  
  - They increase the risk of **side effects**—accidental changes to values by other parts of the program.  
- ⚠️ Name conflicts: If a local variable shares the same name as a global variable, the local variable hides the global one within its block.
