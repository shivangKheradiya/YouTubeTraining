# Function Prototypes

In modern, well‑structured C programs, every function should be declared before it is used. This is typically done using a **function prototype**. Although prototypes were not part of the original C language, they were introduced in C89 and have been a best practice ever since. In C++, prototypes are mandatory.

Function prototypes allow the compiler to perform **strong type checking**, similar to languages like Pascal. With prototypes in place, the compiler can detect:

- Incorrect argument types  
- Mismatches between the number of arguments and parameters  
- Potentially unsafe or unintended type conversions  

Because of these benefits, all examples in this book use full function prototypes.

## General Form of a Function Prototype

```
type func_name(type param1, type param2, ..., type paramN);
```

Parameter names are optional, but including them helps the compiler produce clearer error messages when type mismatches occur.

## Example: Type Checking with Prototypes

The following program demonstrates how prototypes help catch errors. Here, `sqr_it()` expects a pointer to an integer, but the call incorrectly passes an integer value instead.

```c
/* This program uses a function prototype to enforce strong type checking. */
void sqr_it(int *i);  /* prototype */

int main(void)
{
    int x;
    x = 10;
    sqr_it(x);   /* type mismatch */
    return 0;
}

void sqr_it(int *i)
{
    *i = *i * *i;
}
```

Because of the prototype, the compiler will report the incorrect argument type.

## When a Function Definition Serves as Its Own Prototype

If a function is defined **before** it is used, the definition itself acts as the prototype. For example:

```c
#include <stdio.h>

/* This definition also serves as a prototype within this file. */
void f(int a, int b)
{
    printf("%d", a % b);
}

int main(void)
{
    f(10, 3);
    return 0;
}
```

This works in small programs, but in larger projects—especially those spanning multiple files—separate prototypes are essential. For this reason, real‑world C code almost always includes explicit prototypes.

The only function that does not require a prototype is `main()`, since it is the program’s entry point.

## Prototypes for Functions with No Parameters

C and C++ handle empty parameter lists differently:

### In C++
```
int f();   // Function with no parameters
```

### In C
The same declaration means **no parameter information is provided**. The function may take any number of parameters. This is known as an *old‑style function declaration*.

To declare a function with **no parameters** in C, you must use `void`:

```
float f(void);   // Function with no parameters (C)
```

In C++, using `void` is allowed but unnecessary.

## Why Prototypes Matter

Function prototypes:

- Prevent mismatched arguments  
- Catch errors early  
- Improve program clarity  
- Make code more portable and maintainable  

Although prototypes are technically optional in C (for compatibility with very old code), they are **required** in C++. Because of this, most C programmers use full prototypes as standard practice.
