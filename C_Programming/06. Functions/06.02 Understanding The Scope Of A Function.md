# Understanding Function Scope

This section explains how scope operates within C functions and how it affects the visibility and lifetime of variables and code.

## What Is Scope?

Scope refers to the set of rules that determine whether a piece of code can access another piece of code or data. While C defines several types of scope, this document focuses specifically on **function scope**.

## Function Scope Overview

Each function in C forms its own **block scope**. This means:

- The code inside a function is **private** to that function.
- No other function can directly access or jump into the middle of another function’s code.
- The body of a function is isolated from the rest of the program unless it interacts through:
  - **Function calls**, or  
  - **Global variables** (if used).

In other words, the code and data defined within one function cannot interact directly with those defined in another function because each function maintains its own independent scope.

## Local Variables

Variables declared inside a function are **local variables**. Their behavior is defined by:

- **Lifetime:**  
  They are created when the function is entered and destroyed when the function exits.
- **Persistence:**  
  They do *not* retain their values between function calls.

### Exception: `static` Local Variables

A local variable declared with the `static` keyword behaves differently:

- It retains its value between function calls.
- It is stored like a global variable but remains accessible **only within the function**.

## Function Parameters

Function parameters also belong to the function’s scope:

- They are accessible throughout the entire function body.
- They are created when the function is called and destroyed when it returns.

## File Scope of Functions

All functions in C have **file scope**, meaning:

- You cannot define a function inside another function.
- This is one of the reasons C is not considered a fully block‑structured language.
