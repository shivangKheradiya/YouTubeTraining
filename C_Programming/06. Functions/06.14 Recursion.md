# Recursion

In C, a function is allowed to call itself. When it does, the function is said to be **recursive**. Recursion is the process of defining a solution in terms of smaller instances of the same problem—sometimes described as a *circular definition*.

## Example: Computing Factorials Recursively

A classic example of recursion is computing the factorial of an integer.  
The factorial of a number `n` is the product of all whole numbers from 1 through `n`.  
For example:

- `3! = 1 × 2 × 3 = 6`

Below are both recursive and iterative implementations of a factorial function.

### Recursive Version

```c
/* recursive */
int factr(int n) {
    int answer;
    if (n == 1) return 1;
    answer = factr(n - 1) * n;  /* recursive call */
    return answer;
}
```

### Iterative Version

```c
/* non-recursive */
int fact(int n) {
    int t, answer;
    answer = 1;
    for (t = 1; t <= n; t++)
        answer = answer * t;
    return answer;
}
```

The iterative version is straightforward: it multiplies numbers from 1 to `n` in a loop.

The recursive version works by repeatedly calling itself with decreasing values of `n` until it reaches the base case (`n == 1`). At that point, the calls begin returning, and the results “unwind” back up the call chain.

For example, computing `2!`:

1. `factr(2)` calls `factr(1)`
2. `factr(1)` returns `1`
3. `1 × 2` is returned as the final result

You can experiment with `3!` or larger values by adding `printf()` statements inside the function to trace the recursion depth and intermediate results.

## How Recursive Calls Work Internally

Each time a function calls itself:

- A **new set of local variables and parameters** is created on the stack.
- The function’s code begins executing again from the top.
- The function itself is *not* duplicated—only its data changes.

As each recursive call completes:

- Its local variables are removed from the stack.
- Execution resumes immediately after the recursive call in the previous invocation.

This creates a “telescoping” effect as calls expand outward and then collapse back inward.

## Performance Considerations

Although recursion can make certain algorithms clearer and easier to implement, it is not always more efficient:

- Recursive functions often run **slower** due to repeated function call overhead.
- They may use **more memory**, since each call consumes stack space.
- Excessive recursion can cause a **stack overflow**, crashing the program.

Because each recursive call allocates new storage for parameters and local variables, deep or uncontrolled recursion can exhaust the stack.

## When Recursion Is Useful

Despite its drawbacks, recursion is extremely valuable in certain situations:

- Algorithms like **quicksort** are naturally recursive and difficult to express iteratively.
- Many problems in **artificial intelligence**, **tree traversal**, and **graph search** are elegantly solved with recursion.
- Some programmers find recursive thinking more intuitive than iterative approaches.

## Writing Safe Recursive Functions

Every recursive function must include a **base case**—a condition that stops the recursion.  
Without a base case, the function will call itself indefinitely and never return.

A missing or incorrect base case is one of the most common errors in recursive programming.

During development, use `printf()` statements liberally to trace execution and detect runaway recursion early.
