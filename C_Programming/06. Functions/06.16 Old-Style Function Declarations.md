# Old‑Style Function Declarations

Before function prototypes were introduced in C89, C programmers still needed a way to inform the compiler about a function’s **return type** so that it could generate correct code for function calls. Because different data types occupy different amounts of memory, the compiler had to know the return type *before* a function was called.  

This was accomplished using **old‑style function declarations**, which provided only the function’s return type and name—**no parameter information**.

Although this approach is obsolete today, it still appears in older C codebases, so understanding it remains useful.

## Example of an Old‑Style Declaration

```c
#include <stdio.h>

double div();   /* old-style function declaration */

int main(void)
{
    printf("%f", div(10.2, 20.0));
    return 0;
}

double div(double num, double denom)
{
    return num / denom;
}
```

In this example:

- The declaration `double div();` tells the compiler only that `div()` returns a `double`.
- It provides **no information** about the function’s parameters.
- The compiler therefore assumes nothing about the number or types of arguments.

## General Form

Old‑style declarations follow this pattern:

```
type_specifier function_name();
```

The empty parentheses indicate that **no parameter information is supplied**, even if the function actually takes arguments.

## Modern Usage

Old‑style declarations are:

- **Outdated**  
- **Not recommended** for new code  
- **Incompatible with C++**, which requires full prototypes  

Modern C programs should always use full function prototypes to ensure type safety and portability.
